# last-mile-route-verifier

An open-source tool for independently verifying and comparing route distances using a **local OSRM instance** — no proprietary API keys required.

Built to reproduce and validate the results reported in:  
**"Last-Mile Route Optimization at Million-Stop Scale"** — [Medium article](https://medium.com/@martinvizzolini/last-mile-route-optimization-at-1-million-stops-with-near-linear-scaling-e4d4b0118e80)

---

## What this tool does

Given a set of delivery routes encoded as direction URLs, this tool:

1. Parses the origin, destination, and intermediate waypoints from each URL
2. Queries a locally running OSRM server for the actual road distance of each segment
3. Aggregates and reports per-route and total distances in kilometers

The primary use case is comparing two route datasets that cover the **same delivery stops**:

| Input folder | Contents |
|---|---|
| `inputs/amazon/` | Historical routes actually driven by Amazon delivery drivers |
| `inputs/solver/` | Routes generated by the optimization algorithm (same stops, potentially different order) |

By running the tool against both datasets and comparing the total km output, you can independently verify how much distance the solver saves — without relying on any third-party API.

---

## What is OSRM?

**OSRM (Open Source Routing Machine)** is a high-performance routing engine built on top of **OpenStreetMap (OSM)** road network data. It computes shortest-path driving distances using the **Multi-Level Dijkstra (MLD)** algorithm on pre-processed road graphs.

Key properties relevant to this project:

- **Offline and free**: runs entirely on your machine using OSM data downloaded from [Geofabrik](https://download.geofabrik.de/)
- **Deterministic**: given the same map data, it always returns the same distance for the same coordinates — making results fully reproducible
- **Road-aware**: accounts for actual drivable roads, turn restrictions, and one-way streets
- **Fast**: pre-processing the road graph allows sub-millisecond query times at runtime

OSRM is queried via its HTTP API:
```
GET /route/v1/driving/{lon1},{lat1};{lon2},{lat2};...?overview=false
```

The response includes a `distance` field in meters, which this tool converts to kilometers.

## About the input URL format

The direction URLs in the input files look like Google Maps URLs:

```
https://www.google.com/maps/dir/?api=1&origin=LAT,LNG&destination=LAT,LNG&waypoints=LAT,LNG|LAT,LNG&travelmode=driving
```

**Important:** this tool does **not** call Google Maps or any Google service. The URL format is used purely as a portable, human-readable container for coordinate sequences. The tool only reads the `origin`, `destination`, and `waypoints` query parameters and discards everything else.

Why Google Maps URLs? They provide a convenient way to visually inspect any route by pasting the URL into a browser — useful for sanity-checking the data.

**On the 50-stop limit:**  
Google Maps web displays up to 10 stops; the Google Directions API supports up to 25. Each URL in this project encodes up to **50 stops**, which is the maximum OSRM can handle in a single request. This limit was deliberately chosen to maximize throughput: fewer HTTP requests per route means faster total execution time.

---

## Input file format

Each input file (`inputs/amazon/routes.json`, `inputs/solver/routes.json`) is a JSON array of routes. Each route is an array of URL segments. A segment covers a sequence of up to 50 stops.

```json
[
  [
    "https://www.google.com/maps/dir/?api=1&origin=LAT,LNG&destination=LAT,LNG&waypoints=LAT,LNG|...",
    "https://www.google.com/maps/dir/?api=1&origin=LAT,LNG&destination=LAT,LNG&waypoints=LAT,LNG|..."
  ],
  [
    "https://www.google.com/maps/dir/?api=1&origin=LAT,LNG&destination=LAT,LNG&waypoints=..."
  ]
]
```

Structure summary:
- **Outer array**: one entry per route (e.g., one delivery driver's full day)
- **Inner array**: one URL per segment of that route (each URL covers up to 50 stops)
- **URL**: encodes the ordered sequence of stops for that segment

The `inputs/` folder ships with example files using sample coordinates. Replace them with your actual dataset when reproducing results.

================================================================
  ROUTE SUMMARY

**What each value means:**

| Field | Description |
|---|---|
| `stops` | Total coordinate points in the segment (origin + waypoints + destination) |
| `km` per segment | Road distance in kilometers as computed by OSRM for that segment |
| `km` per route | Sum of all segment distances for that route |
| `TOTAL DISTANCE` | Sum across all routes — the number to compare between `amazon/` and `solver/` |

- **Docker** (for OSRM and/or the verifier container)
- **Python 3.8+** (only if running the script natively without Docker)
- OSM map data for your target region (downloaded once, stored in `data/`)

## Setup — download and pre-process map data

This step is required once per region. The output files are stored in `data/<region>/` and reused on every subsequent run.

### 1. Download OpenStreetMap data

Go to [Geofabrik](https://download.geofabrik.de/) and download the `.osm.pbf` file for your region:

```bash
mkdir -p data/massachusetts
cd data/massachusetts
wget https://download.geofabrik.de/north-america/us/massachusetts-latest.osm.pbf
cd ../..
```

### 2. Pre-process the map data with OSRM

Run these three commands in sequence. Each step builds on the output of the previous one. This is a one-time operation — the resulting files are reused every time OSRM starts.

```bash
# Step 1 — Extract: parse OSM data and build the routing graph
docker run --rm --platform linux/amd64 \
  -v "$(pwd)/data/massachusetts:/data" \
  osrm/osrm-backend \
  osrm-extract -p /opt/car.lua /data/massachusetts-latest.osm.pbf

# Step 2 — Partition: split the graph into cells for MLD routing
docker run --rm --platform linux/amd64 \
  -v "$(pwd)/data/massachusetts:/data" \
  osrm/osrm-backend \
  osrm-partition /data/massachusetts-latest.osrm

# Step 3 — Customize: compute routing weights for each cell
docker run --rm --platform linux/amd64 \
  -v "$(pwd)/data/massachusetts:/data" \
  osrm/osrm-backend \
  osrm-customize /data/massachusetts-latest.osrm
```

> **Note:** Pre-processing a state-sized region takes several minutes and ~1.5 GB of disk space.

## Running with Docker (recommended)

### Configure environment

```bash
cp .env.example .env
# Edit .env if your region or port differs from the defaults
```

### Step 1 — Start the OSRM server

```bash
docker compose up osrm -d
```

Wait a few seconds for OSRM to load the road graph. The health check will confirm it's ready.

### Step 2 — Run the verifier

Verify Amazon historical routes:

```bash
docker compose run --rm verifier \
  --input inputs/amazon/routes.json \
  --osrm  http://osrm:5000
```

Verify solver-generated routes (same stops, different order):

```bash
docker compose run --rm verifier \
  --input inputs/solver/routes.json \
  --osrm  http://osrm:5000
```

Compare the `TOTAL DISTANCE` values from both runs to quantify the solver's improvement.

### Step 3 — Stop the OSRM server

```bash
docker compose down
```

## Running natively (without Docker for the verifier)

### Install Python dependencies

```bash
pip install -r requirements.txt
```

### Start OSRM

```bash
./run_osrm.sh massachusetts 5002
```

### Run the verifier

```bash
# Amazon routes
python scripts/check_distance_osrm.py \
  --input   inputs/amazon/routes.json \
  --osrm    http://localhost:5002 \
  --workers 6

# Solver routes
python scripts/check_distance_osrm.py \
  --input   inputs/solver/routes.json \
  --osrm    http://localhost:5002 \
  --workers 6
```

### CLI options

| Option | Default | Description |
|---|---|---|
| `--input` | *(required)* | Path to the JSON input file |
| `--osrm` | `http://localhost:5002` | Base URL of the OSRM server |
| `--workers` | `6` | Number of parallel threads for OSRM queries |

## Reproducing paper results

To reproduce the distances reported in the paper using the Amazon Last Mile Routing Research Challenge dataset:

1. Download the dataset from [AWS Open Data](https://registry.opendata.aws/amazon-last-mile-routing-research/)
2. Extract historical route sequences and convert them to the JSON URL format described above, using the region's coordinates
3. Download and pre-process the OSM data for the corresponding US state (e.g., Massachusetts)
4. Run both `inputs/amazon/` and `inputs/solver/` through this tool and compare totals
