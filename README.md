# last-mile-route-verifier

A tool to **independently verify and compare last-mile delivery route distances** using a local routing engine. No proprietary APIs, no cloud services.

Built to reproduce the results from:
**"Last-Mile Route Optimization at Million-Stop Scale"** — [Medium article](https://medium.com/@martinvizzolini/last-mile-route-optimization-at-1-million-stops-with-near-linear-scaling-e4d4b0118e80)

---

## What this tool does (and doesn't do)

**Does:**
- Reads pre-computed route plans from JSON files and measures their actual road distance using OSRM
- Compares Amazon historical routes against solver-generated routes for the same delivery stops
- Generates interactive HTML maps with per-route stop counts, distances, and sequence overlays

**Does not:**
- Plan or optimize routes — the solver has already run; this tool only verifies its output
- Call Google Maps or any external API — the Google Maps URL format is used purely as a coordinate container, parsed locally

---

## How it works

The input files store delivery routes as lists of Google Maps direction URLs. Each URL encodes up to 50 GPS stop coordinates in its `origin`, `waypoints`, and `destination` query parameters. The tool parses those coordinates and queries a local OSRM server to compute the actual road distance of every segment.

Run it on both the Amazon dataset and the solver dataset for the same depot, then compare `TOTAL DISTANCE`. The difference is the solver's verified improvement.

> You can paste any URL from the JSON directly into a browser to inspect the stops visually on a map. That's the only role the URL format plays here.

---

## Amazon routes vs solver routes

The `inputs/` folder contains two datasets for each depot, both covering **the exact same delivery stops**:

| Folder | What it contains |
|---|---|
| `inputs/amazon/` | Historical routes actually driven by Amazon delivery drivers, reconstructed from GPS tracking data. These represent how deliveries were executed in practice. |
| `inputs/solver/` | Routes generated by an optimization solver for the same stops — re-sequenced and redistributed across vehicles to minimize total driving distance. |

This tool **does not run the solver**. The JSON files are the solver's pre-computed output. The verifier measures the road distance of each plan independently, so the improvement claim can be reproduced without trusting the solver's own reporting.

**Solver constraints:** the optimized routes were built under real operational constraints — maximum stops per route, vehicle weight and volume capacity, and delivery time windows. Only the resulting GPS coordinates are stored in the JSON files; weights and volumes are not visualized.

## Quick Start — DBO1 (Boston area)

The `DBO1` dataset is included and covers the Boston area. The **Massachusetts** OSRM map is required.

> A running OSRM server is required before executing the verifier.

### 1. Pre-process the map (one-time per region)

```bash
mkdir -p data/massachusetts
wget https://download.geofabrik.de/north-america/us/massachusetts-latest.osm.pbf \
     -O data/massachusetts/massachusetts-latest.osm.pbf

docker run --rm --platform linux/amd64 \
  -v "$(pwd)/data/massachusetts:/data" osrm/osrm-backend \
  osrm-extract -p /opt/car.lua /data/massachusetts-latest.osm.pbf

docker run --rm --platform linux/amd64 \
  -v "$(pwd)/data/massachusetts:/data" osrm/osrm-backend \
  osrm-partition /data/massachusetts-latest.osrm

docker run --rm --platform linux/amd64 \
  -v "$(pwd)/data/massachusetts:/data" osrm/osrm-backend \
  osrm-customize /data/massachusetts-latest.osrm
```

> Takes a few minutes and ~1.5 GB of disk space.

### 2a. Run natively

```bash
pip install -r requirements.txt
./run_osrm.sh massachusetts 5002

# Amazon historical routes
python3 scripts/check_distance_osrm.py \
  --input   inputs/amazon/routes_result_DBO1_AMZ_60.json \
  --osrm    http://localhost:5002 \
  --workers 6
# → prints TOTAL DISTANCE and saves map to maps/AMZ_DBO1.html

# Solver-optimized routes
python3 scripts/check_distance_osrm.py \
  --input   inputs/solver/routes_result_DBO1_56.json \
  --osrm    http://localhost:5002 \
  --workers 6
# → prints TOTAL DISTANCE and saves map to maps/SOLVER_DBO1.html
```

### 2b. Run with Docker

```bash
cp .env.example .env
# Set OSRM_REGION=massachusetts in .env

docker compose up osrm -d

docker compose run --rm verifier \
  --input inputs/amazon/routes_result_DBO1_AMZ_60.json \
  --osrm  http://osrm:5000

docker compose run --rm verifier \
  --input inputs/solver/routes_result_DBO1_56.json \
  --osrm  http://osrm:5000

docker compose down
```

> Inside Docker Compose use `http://osrm:5000`. Natively, use `http://localhost:5002`.

## CLI reference

| Option | Default | Description |
|---|---|---|
| `--input` | required | Route JSON file |
| `--osrm` | `http://localhost:5002` | OSRM server URL |
| `--workers` | `6` | Parallel threads for OSRM queries |
| `--map` | auto from filename | HTML map output path |
| `--no-map` | off | Skip map generation |
| `--label` | auto from filename | Map panel title |

Map path and label are inferred from structured filenames (e.g. `routes_result_DBO1_AMZ_60.json` → `maps/AMZ_DBO1.html`, title `DBO1 AMAZON (OSRM)`). Pass both flags explicitly for generic filenames.

## HTML maps — standalone (no OSRM needed)

`generate_map.py` builds an interactive map directly from any route JSON — no OSRM or Docker required. Useful for quickly inspecting stop locations and route coverage before running the full verification.

```bash
# Single dataset
python3 scripts/generate_map.py \
  --input   inputs/amazon/routes_result_DBO1_AMZ_60.json \
  --output  maps/DBO1_amazon.html \
  --label-a "DBO1 Amazon"

# Side-by-side comparison with layer toggle
python3 scripts/generate_map.py \
  --input   inputs/amazon/routes_result_DBO1_AMZ_60.json \
  --compare inputs/solver/routes_result_DBO1_56.json \
  --output  maps/DBO1_comparison.html \
  --label-a "Amazon" --label-b "Solver"
```

Maps generated by `check_distance_osrm.py` also include OSRM-verified km per route in each stop popup.

## Alternative: OpenRouteService (no Docker)

[OpenRouteService (ORS)](https://openrouteservice.org/) is a free online routing API that accepts the same input format. Useful when you don't want to download or pre-process regional map files.

```bash
export ORS_API_KEY=your_key_here
python3 scripts/check_distance_ors.py \
  --input inputs/amazon/routes_result_DBO1_AMZ_60.json
```

**Free tier:** 2,000 req/day, 40 req/min. The script defaults to 1.6 s between requests. For large datasets, OSRM is significantly faster. A 1–3% difference between ORS and OSRM results is normal.
